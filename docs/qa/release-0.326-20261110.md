# 0.326 통합 검증 — 2026-11-10

0.325 이후 완료된 해적 현상수배·옛이야기·교역 업적·가족 성장과 항해·보상·도크 안내·그림 보완을 정식·베타 배포 대상으로 고정했다. Git 추가 목록으로 배포용 사본을 만들고 같은 사본에서 두 웹을 빌드한다. 작업 중인 원본·사용하지 않는 초상 이전본은 작업 폴더에 보존한다.

## 기능과 저장 호환

- 해적: 바다별 이름난 해적 수·실존/창작 구분·해적단 68개, 식당 벽보·현상금 수령·입항당 소문·여급 안내·실제 함대 출현, 깃발 획득과 보관함 대체, 같은 바다의 잔당 흡수와 배·선원·포술·두목·현상금 증가를 검사했다. 첫날 지급 기록의 값 0도 수령 완료로 처리해 중복 지급을 막는다.
- 옛이야기: 셔우드의 대회·탈출·선택 후 배트 후드와 캐시 합류, 라푼젤의 탑·마녀·구조, 텔의 사과·폭풍·탈출과 합류, 거절·실패·재시도·소문·이전 저장을 검사했다. 로빈 후드와 마리안은 셔우드에 남는 역할을 유지한다.
- 교역: 한 품목·모두 팔기·일괄 매각의 한 번 이익을 기록한다. 100만 닢 미만/이상, 각 대륙 업적과 중복 지급 방지, 1500년 네 대륙과 1790년 오세아니아를 포함하는 교역왕 조건, 교역 명성·칭호·금화·달성 장면을 확인했다.
- 가족: 성년 아들·미혼 딸의 항해사 합류·역할·선실·집으로 복귀·견습의 성년 전환, 독립·편지·재합류·후계, 저장 복원을 확인했다. 같은 교육을 받는 자녀 300명의 성장 비교, 그릇과 돌파 확률·좋은 해/힘든 해·성년 전 특기 2단계·지력별 습득률과 어머니의 언어·특기를 검사했다. 이전 저장에 있던 언어 3단계를 교육이 낮추지 않는다.
- 배우자: 모국어 습득·선실과 통역·사별/이별 뒤 유지, 제독 정보창의 본인/동료 보완 표시를 반영했다. 언어 규칙은 항해 속력 식을 바꾸지 않는다.
- 점령·발견: 도시별 점령 명성·악명과 사전 안내·성공 후 기록, 발견 보상 배수 1.8과 후원자 보고·늦은 보고·소지품·전투 회귀를 검사했다. 선금과 명명권 값은 변경 대상이 아니다.
- 도크: 모항 10척과 일반 항구 3척, 기함·도크 만석·교역품/식량/물/자재/의뢰 짐 때문에 맡길 수 없는 경우의 설명, 적재량 계산·배 선택·보관과 찾기를 확인했다.

## 통합 검사에서 고친 문제

새 옛이야기 모듈이 기존 민족 마을의 `G.Folk`를 덮어써 입항 때 `town is not a function` 오류가 발생했다. 옛이야기는 `G.Folktales`로 연결하고 민족 마을은 기존 기능을 유지한다. 통합 회귀 시험에서 두 기능의 공존, 첫날 현상금과 이전 언어 단계 보존을 실제 게임 경로로 확인했다.

모조품·경쟁 탐험가 시험의 첫 실패는 0.325 사본에서도 재현했다. 모조품 시험은 문자열로 넣던 단서를 현재 객체 형식으로 바꾸고, 옥살이 중 다른 사건·업적의 명성 변동과 구별해 직접 감점 10%를 검사한다. 경쟁 시험은 고정 역사 사건 함대와 최초 발견 경쟁 함대를 구분해 각각 사건 제어기와 발견자 연결을 검사한다. 이어 확인된 콜럼버스·드레이크 항로의 육지 위 점 6개를 가까운 바다 칸으로 조정했다. 날짜와 함대 ID는 보존하며 두 항해 이야기의 전체 시험도 재확인했다.

민족 그림 파일 시험은 기존 업적 내용을 보존하되 끝에 추가된 교역 업적 6개를 허용하도록 갱신했다. 초상 짝 시험은 검증한 7명의 경로·해시 자료를 버전 관리하는 도구 자료에서 읽는다. 해당 민족 원화 시험의 제작 원본과 변경 전 자료는 로컬 제작 폴더를 사용한다.

## 그림과 검증

배포에 쓰이는 새 그림·교체 그림 597개를 해독하고 규격·프레임·투명도·SHA-256을 기록했다. 해적 수배서 170장·깃발 68종의 실제 소지품/벽보/상세 화면, 옛이야기 인물 13명의 얼굴·무릎상과 사건 장면 5개·합류 4명·도감, 누락 사건 133개 항목 전체의 실제 표시, 인물 20명의 대화, 초상 짝 교정 7명, 민족 발견 18종의 움직임·장면 판·막야·혼인 업적을 확인했다. 이전 배포의 미완성 그림만 검사하는 `--partial` 대신 이번에는 133개 전체 검사를 통과했다.

JavaScript 541개 문법 검사와 브라우저 기능 시험 45개, 원화 파일 시험 1개를 통과했다. 이 가운데 그림 전달 보완 뒤 추가한 시험은 원격 그림의 캔버스 읽기·PNG 내보내기·WebGL 업로드와 로컬 파일 실행을 확인한다. 최종 결과와 첫 실패·재검사 로그는 `artifacts/release-0.326-20261110/`에 보존한다. 원화의 실제 활성 경로를 기준으로 배포 대상을 고르고 이전본 16개는 런타임 배포에서 제외한다.

## 웹 빌드와 공개 이력

고정한 소스에서 정식·베타 압축 웹 빌드를 만들었다. 각 빌드의 그림 목록은 16,323개 논리 키이며, 새/교체 파일 597개씩과 해적·옛이야기·가족·보상·도크 모듈, 도감·포탈과 390px 화면을 검사한다. 생성한 그림 목록은 같은 Git 추가 목록에 반영해 서버 빌드와 일치시킨다.

베타 포탈에 기능 중심의 0.326 이력을 추가하고 기존 공개 이력·배포 노트·게임 출처에서 요청한 작성 도구 이름 표현이 없는지 확인한다. 공개 게시 완료 후 두 웹의 버전·597개 그림씩의 해시, 도감 기록·통합 회귀·포탈을 다시 확인한다.

브라우저는 `finally`에서 닫고 종료 여부를 확인한다. 로컬 서버는 사용하지 않는다.

## Pages 게시 용량 보완

첫 게시에서는 약 6.4GB 묶음의 파일 동기화 중 10분 제한에 도달했다. 게시 단계만 재시도했을 때도 제한 시간 안에 완료되지 않았다. 30분을 넣어 두었던 입력도 게시 동작의 최대 10분으로 제한되는 것을 실제 로그에서 확인했다. [GitHub Pages 공식 한도](https://docs.github.com/en/pages/getting-started-with-github-pages/github-pages-limits)는 게시 사이트 1GB·배포 10분이다.

그림 파일의 바이트와 해상도를 유지한 채 같은 공개 저장소의 커밋 고정 주소를 사용하도록 웹 빌드에 `--image-base`를 추가했다. 캔버스와 WebGL에서 그림을 읽을 수 있도록 익명 CORS를 설정하고 도감 파일 링크도 같은 기준 주소를 사용한다. 시작 화면의 불러오기 그림과 출처 문서는 Pages에 함께 둔다. 로컬 파일 실행과 일반 오프라인 빌드는 기존 폴더를 계속 사용한다.

정식·베타를 합쳐 공용 자산을 정리한 게시 폴더는 228,906,365 bytes(218.3 MiB)다. 게시 전에 `tools/check_pages_size.py`로 1GB 한도를 검사한다. 원화에 축소·재압축은 적용하지 않는다. 이전 그림 전달 방식의 빌드 기록도 보존하고, 새 방식의 두 웹에서 597개 파일씩의 해시·그림 표시·통합 동작을 재검사한다.

새 전달 방식의 두 빌드에서 그림 597개씩 SHA-256 일치와 오류 0을 확인했다. 두 채널의 그림 읽기·통합 회귀·도감 기록 검사와 포탈 390px 화면도 통과했다. pages-checks.json의 독립 웹 검사 7개를 보존한다.
