# 남는 부하의 빈 선실 거주 — 2026-11-01

기함의 `hold`(빈 선실)를 거주용 선실로 쓴다. 자동 배치는 효과를 내는 직무 선실과 다른 배의 보직을 먼저 채우고, 남는 부하를 빈 선실에 한 명씩 배치한다. 모든 자리와 선실이 찼을 때만 초과 인원이 대기로 남는다. 기존 자동 채우기 시점(도시 입장·합류·출항·선실 화면·기함 변경·해전 뒤·월별 충성 계산)에 함께 적용한다.

## 규칙과 저장

- 기함 빈 선실도 `mate.room`·`roomType: 'hold'`로 기록한다. 선실 정리·개조·기함 변경·저장 후 불러오기에서 같은 방식으로 보존한다.
- 빈 선실은 다른 배의 거주 선실과 같은 기존 배치 우선값 `G.BALANCE.crewAuto.berth`를 사용한다. 직무 선실과 다른 배의 보직보다 낮은 우선순위다.
- 빈 선실 거주자도 빈 직무 자리가 생기면 자동 배치 후보가 된다. 이미 맡은 기함 보직·직무 선실과 손으로 정한 다른 배 선장은 기존 편성 규칙을 따른다.
- 거주자는 대기로 표시하지 않고, 월별 대기 충성 감소를 받지 않는다. 거주용 선실의 직무 효과·특기 수련은 없다.
- 창고(`store`)에는 사람을 배치하지 않는다. 창고로 개조할 때는 거주 배치를 해제한다.
- 선실 화면의 카드·배치 목록·팝업·끌어다 놓기에서 빈 선실을 선택할 수 있다. 조선소의 선실 개조도 같은 팝업에서 고를 수 있다.
- 튜토리얼 중 수동 선실 배치를 배우는 기존 흐름과, 선실 창 안에서 손으로 잠시 대기로 빼는 기존 조작은 유지한다.

코드: `js/systems/crewauto.js`, `js/systems/cabins.js`, `js/ui/cabinview.js`, `js/data/cabins.js`.

## 검증

- `node tests/empty_cabins_smoke.cjs`: 빈 선실 자동 배치·정원 초과 대기·중복 금지·반복 배치 안정·충성 처리·저장·개조·기함 변경·직무 우선·손으로 정한 선장 보호를 검사한다. 실제 선실 팝업을 열고 부하를 다른 빈 선실로 옮기는 조작도 통과했다.
- `tests/cabin_growth_smoke.js`: 기존 선실 특기 수련 12개 검사 통과.
- `tests/cabin_store_smoke.js`: 창고 적재량·사람 배치 금지·개조·실제 화면 회귀 검사 통과.
- `tests/crew_auto_smoke.js`: 기함과 다른 배의 자동 편성·충성·기함 변경·옛 저장·자동 배치 단추·편성 화면 회귀 검사 통과. 빈 선실도 모두 쓴 뒤 남는 인원만 대기하도록 기존 기대값을 갱신했다.
- Chromium `file://`에서 검사했으며 `pageerror`·`console.error` 0. 각 브라우저는 `finally`에서 닫는다.

이 환경에서는 기존 시험의 `playwright` 요청을 설치된 `tools/procedural_art/node_modules/playwright-core`로 연결하고 `BROWSER_EXE`에 로컬 Chrome을 지정했다.

결과와 실제 선실 화면은 `artifacts/empty-cabins-20261101/report.json`, `empty-cabin-residents.png`에 남긴다. 배포·버전 변경은 이번 변경에 포함하지 않는다.
