# 식당 소문과 바다의 현상수배 해적 (2026-11-17)

식당의 「손님들의 해적 이야기를 듣는다」로 얻은 소문의 앞바다에 기한 안에 들어가면 해당 이름난 해적 함대가 나타난다. 일반 함대 출현에 밀리지 않도록 소문을 먼저 검사하고, 항해 중 0.5초마다 확인한다. 이미 바다에 같은 선장이 있으면 그 함대를 소문과 연결한다.

소문 속 해적은 출현 지점 둘레를 배회한다. 1.4도 안으로 다가가면 기존 전용 수배서 초상·이름·현재 현상금을 사용한 종이가 바람에 날아와 펼쳐진다. 창을 확인하는 동안 항해를 멈추며, 같은 함대에서는 한 번만 보여 준다. 직접 해적을 눌러 마주쳐도 연출이 선행한다. 전투·토벌 보상은 기존 규칙을 따른다.

조정값은 `G.FX.wantedReveal`: 근접 1.4도, 소문 검사 0.5초, 비행 1500ms, 배회 반경 1.8도. 옛 저장의 소문에도 새 필드를 요구하지 않는다.

## 반복 처리 줄이기

- 항해 세부 이동 단계마다 계산하던 측량 시야를 한 프레임에 한 번 계산한다. 해도 기록은 각 이동 단계에서 계속 수행한다.
- 항구·육상 도시 근접 검사에서 위도 차이로 먼 도시를 먼저 제외한다.
- 육상 탐험의 상태·귀환 단추는 표시가 바뀔 때만 DOM을 고친다.
- 탐험 화면의 함대 동기화에서 탐험 함대 명부는 한 번만 조회하고 ID 색인으로 비교한다. 사라진 배의 방향 연출 자료도 해제한다.

## 검증

- `node tests/wanted_sea_reveal_smoke.cjs`: 실제 식당 소문, 실제 바다 갱신 출현, 중복 방지, 근접 연출, 창 닫은 후 busy 해제, 재표시 방지, 탐험 함대 명부 조회 1회, 브라우저 오류 0건.
- `BROWSER_EXE`를 설치된 Chrome 경로로 지정한 `node tests/pirate_wanted_smoke.js`: 전부 통과.
- `node tests/runtime_perf_browser.cjs wanted-sea-20261117`: 항해·탐험·전투 전환, 시간 배분, 원본 해상도, 중첩 전투 정지·복귀, 그래픽 자원 해제 통과. 보고서 `artifacts/runtime-perf-20261115/wanted-sea-20261117/report.json`.
- 화면: `artifacts/wanted-sea-20261117/reveal.png`.

배포는 수행하지 않았다. 모든 기기·장시간 저장에서 발생 가능한 끊김을 없앴다고 단정하지 않는다.

## 2차 연출 수정

설명창을 제거하고 바다 위 투명 전경에 수배서 자체를 띄운다. 2600ms 동안 좌우 바람결을 따라 날고 3D 회전으로 뒤집힌 뒤, 1100ms 동안 세 조각 종이의 접힌 양옆을 차례로 펼친다. 바람 궤적과 접힘 그림자, 펼친 뒤 잔흔들림을 사용한다. 설명 문구는 없고 수배서 인쇄 내용만 남는다. 펼침이 끝나면 종이·바깥 배경·닫기 아이콘 또는 Escape/Enter로 닫는다. 장면 종료 시 타이머·키 처리·전경을 정리한다.

시험은 비행·펼침 중·완성의 CSS 변환이 서로 다른지, 세 접힘 면과 설명 문구 제거, 실제 바다 배경, 창 종료 후 항해 잠금 해제까지 검사한다. 단계별 화면은 같은 아티팩트 폴더의 `flying.png`, `unfolding.png`, `opened.png`다.
