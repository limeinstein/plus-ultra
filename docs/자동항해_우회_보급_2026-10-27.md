# 자동항해 목적지의 우회 항로·보급 표시 수정

## 제보와 원인

아시아에서 유럽으로 자동 이동할 때 아프리카를 돌아야 하는데, 이집트 항구가 유럽보다 가까운 곳으로 표시되고 선택한 뒤에야 보급 부족 경고가 나왔다.

`G.Routes.roughDays`는 익힌 항로의 경유 날수 합과 직선거리 어림 가운데 작은 값을 택했다. 이 때문에 지중해·홍해 사이의 육지를 가로질러 계산한 값이 목록 정렬과 보급 표시를 짧게 만들었다. 또한 보급이 어림의 세 배 이상이면 출항 전 실제 뱃길을 확인하지 않았고, 과거의 가장 빠른 항해 기록을 현재 함대의 계산보다 우선했다.

## 변경

- `js/systems/routes.js`: 아직 측정하지 않은 경유 항로는 익힌 구간들의 날수 합을 사용한다. 실제 길을 측정한 뒤에는 그 길을 현재 선속으로 환산한 값을 우선한다. 새 측정 결과가 생기면 경유 날수 캐시도 갱신한다.
- `js/city/harbor.js`: 목록에서 경유 날수에 맞춰 정렬·보급 부족을 표시하고, 선택한 목적지는 항상 실제 뱃길·현재 선속·현재 보급으로 확인한다. 길을 찾지 못하면 출항하지 않는다. 목록을 열 때 모든 항구의 길찾기를 실행하지 않는다.
- 조정값·저장 형식·배의 실제 속도·항해 경로 선택 방식은 바꾸지 않았다. 기존 저장의 항해 기록을 그대로 사용한다.

경유 구간 합은 보수적인 어림이다. 중간 항구들을 일일이 거치던 항로보다 직접 뱃길이 짧으면 목적지를 고른 뒤 예상이 줄어들 수 있다. 측정 결과는 다음 목록부터 재사용한다.

## 재현과 검증

실제 지형의 캘리컷→케이프→리스본→알렉산드리아 항로로 확인했다.

| 항목 | 시험 결과 |
| --- | --- |
| 기존 캘리컷→알렉산드리아 직선 어림 | 95일 |
| 수정 후 리스본까지 경유 어림 | 186일 |
| 수정 후 알렉산드리아까지 경유 어림 | 235일 |
| 시험 보급 | 210일분 |
| 선택 전 목록 | 리스본이 먼저, 알렉산드리아에는 `보급 모자람` 표시 |
| 해당 목록 생성 | 약 0.7ms, 길찾기 호출 0회 |

숫자는 시험 함대의 조건에 따른 값이다. 화면은 `artifacts/autodest-detour-list.png`.

검사:

- `node tests/autodest_detour_smoke.js`: 수정 전 71일과 155일의 불일치로 실패하는 것을 확인한 뒤 수정 후 통과. 경유 합·정렬·보급·측정 후 갱신·속력 변경을 확인한다.
- `node tests/autodest_detour_browser.js`: 실제 아프리카 우회 목록, 선택 전 경고, 보급이 넉넉해 보이거나 옛 최단 기록이 있어도 실제 길 재확인, 현재 보급 증감, 길 없음 처리. 페이지·콘솔 오류 0.
- `node tests/autodest_smoke.js`: 소수 항구·지역/대륙 묶음·즐겨찾기·실제 목적지 선택. 외부 글꼴 연결 때문에 검사가 지연되지 않도록 글꼴 요청을 고정하고 DOM 준비 뒤 검사한다.
- `node tests/route_net_smoke.js`: 항로망 연결·분리·저장·불러오기.
- `node tests/route_perf_smoke.js`: 60항구 체인·큰 항로망·목적지 선택 후 갱신·실제 바다 경로·보급 부족·없어진 항구·저장 재로딩. 기존의 직선거리와 비슷한 어림을 요구하던 검사는 익힌 구간 합과 측정 후 갱신을 확인하도록 바꿨다.

시험 브라우저는 모두 `finally`에서 닫는다. 배포는 수행하지 않았다.
