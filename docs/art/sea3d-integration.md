# 보강 선박의 본편 항해 적용 (2026-10-31)

[본편 게임](../../index.html)의 항해 화면에서 보강한 36종 모형을 사용한다. 기존 기함 연결을 동행선·호위 상선·주변 상선·함대·해적선으로 넓혔다. [미술과 자료 기록](rig3d-references.md), [선박 작업실](../../test_ship_details.html)의 모형과 동일하다.

## 연결

- `js/scenes/sea.js`: 항해 화면의 세 가지 선박 표시 경로에 실시간 3D를 적용한다. 풍향, 돛 접기, 노젓기, 파도에 따른 자세, 해일의 흔들림과 날씨 조명을 전달한다. 이미 있는 선종 ID와 깃발 구분을 사용한다.
- `js/art/ship3d.js`: `beginFrame`·`endFrame` 사이에서 보이는 선종을 재사용한다. 같은 선종의 여러 배도 하나의 모형을 각각의 상태로 갱신해 그린다. 그래픽 장치는 선박 전체에 하나이며, 화면에 없는 모형은 최근 3종까지 보관한다. 장면 종료 시 보관된 모형까지 해제한다.
- 같은 모형으로 해적선과 아군을 번갈아 그릴 때 돛 색과 깃발이 섞이지 않도록 매번 원래 재질에서 갱신한다. 별도의 선박 상태나 저장 필드를 추가하지 않는다.
- `G.FX.ship3d.idleModels`는 화면 밖 모형 보관 수, `pirateSailTint`는 해적선 돛 색이다. 선박 기본 크기·속력·항로·파도 식은 유지한다. 이후 적용한 [지도 확대와 기본 선명도](sea-zoom.md)는 표시 크기를 지도 배율에 연결하고 기존 해안 판정을 보존한다.
- 장치 손실·미지원 선종에는 기존 그림 경로를 사용하고 복구 후 3D로 돌아온다. 해전·육상 장면의 선박 표시는 이번 변경 범위 밖이다.

## 검증

`tests/sea3d_integration.cjs`는 `index.html`을 `file://`로 열고 실제 항해 장면을 검사한다.

- 기함·동행선 5척, 호위 상선 1척과 주변 상선·함대·해적선 9척의 동시 표시
- 36종 모두 실제 함대·호위선 자리에서 사용하고 기존 그림으로 빠지지 않는지 확인
- 같은 함대를 반복 그릴 때 모델 생성 수·GPU 모형·텍스처 수가 늘지 않는지 확인
- 같은 선종의 돛 접기·깃발·해적 돛 색을 번갈아 적용한 뒤 원래 그림이 정확히 복원되는지 확인
- 선회·돛 전개/반 접기/접기, 장치 손실과 복구, 화면 밖 모형 정리, 항해 종료·재진입
- 렌더링 전후 저장 상태 불변과 콘솔 오류 0

[GPU 결과](../../artifacts/sea3d-20261031/gpu/report.json)와 [SwiftShader 결과](../../artifacts/sea3d-20261031/software/report.json)는 별도로 남긴다. [실제 항해 화면](../../artifacts/sea3d-20261031/gpu/sea-fleet.png). 단일 선박 경로는 기존 `tests/ships3d_smoke.cjs`의 36종 방향·돛·노·경계·자원 검사로 확인한다.

본편 소스 실행은 `index.html`이다. 단일 파일판·설치 파일은 각 배포 도구가 같은 스크립트 목록을 묶으며, 이미 만들어진 과거 배포본을 이 소스 수정만으로 갱신하지는 않는다.
