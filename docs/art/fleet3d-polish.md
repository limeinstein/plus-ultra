# 36종 실시간 선박 미술 · 2026-10-31

갤리온에서 검증한 미술 보강 과정을 `realtime-ship-art` 스킬로 만들고, 해당 절차를 적용해 나머지 35종도 보강했다. 현재 항해 기함은 36종 모두 실시간 3D로 표시한다. 선종별 형태와 크기·게임 능력치·저장 데이터는 유지한다.

## 두 번째 미술 보강

같은 스킬로 36종을 다시 검토하여 다음 구조를 보강했다. [추가 보강 전후 화면](fleet3d-polish2.html)에서 동일한 방향·조명의 이미지를 슬라이더로 비교할 수 있다.

- 돛 가장자리를 입체 밧줄로 감쌌다. 사각돛의 짧은 리프 줄, 겹친 모서리 보강천과 부분 수선 자국, 가장자리 잔주름도 추가했다. 테두리 줄은 실제 천 꼭짓점을 따라 회전·접기·바람 변형을 함께 받는다.
- 해치 둘레에 두꺼운 나무틀과 윗테를 더해 격자 덮개가 안쪽으로 들어가 보이게 했다. 선루와 돛대 자리를 확인해 닻줄을 감는 가로 원통·지지대·손잡이를 배치했다.
- 선미 타와 고정 쇠띠·못, 공간이 있는 선미의 조타 손잡이를 추가했다. 정크는 기존 타에 쇠띠만 더하며, 부판선과 발사는 긴 조타 노를 쓴다. 부리형 선수에는 작은 난간과 가로 격자를 붙였다.
- 갑판집에 처마 절단면·서까래·박공 틀·문과 문턱을 추가했다. 거북선에는 둥근 등판을 따라가는 패널 이음을 보강하고, 용머리 아래 비어 있던 부분을 굽은 목과 고정판으로 선수에 연결했다.

정적 부품은 기존 재질별 합치기에 포함된다. 동적 돛줄은 한 개의 인스턴스 메시로 묶어 돛줄 자체에 한 번의 그리기 호출을 쓴다. `G.FX.ship3d`의 `sailRopeRadius`, `reefRopeLength`, `sailWrinkle`과 `G.FX.shipArt.families.west.boltRope`에서 두께·길이·잔주름·색을 조절한다.

검토 자료는 `artifacts/fleet3d-polish2-20261031/`에 있다. `before/`는 추가 보강 전 네 장을 보존하며, `gpu/`와 `software/`는 현재 검사 결과다. `sail-folds.png`는 네 가지 돛의 전개·반 접기·접기를 비교한다. `gpu/detail-*.png`는 갤리온·다우·보선·거북선·코라코라·발사의 확대 모습이다.

## 확인하기

`test_ships_3d.html`을 더블클릭한다. 선박 선택이나 이전/다음 배 버튼으로 36종을 바꾸고, 기존 그림과 보강된 실시간 모델을 비교한다. **세부 장식 살펴보기**에서는 더 크게 표시한다. 방향·바람·돛 접기·파도·구름을 조절할 수 있다.

게임에서는 해당 선종을 기함으로 삼고 출항한다. 동행선·NPC·해전은 이번 작업의 적용 범위에 포함하지 않았으며 기존 그림을 쓴다. 바다는 기존 지도 렌더러다.

돛은 1024px 절차적 재질에 천 폭·솔기·바느질·보강천을 넣었다. 직조 돛과 대나무 살 돛은 재질을 구분한다. 목재·돛천의 미세 요철과 선종별 팔레트도 적용했다. 갤리온에는 기존의 청록색 회랑·금박·구명정 등 승인된 장식을 유지했다.

## 구현과 조정

- `tools/ship3d/ship_detail_materials.js`: 갤리온에서 추출한 공용 목재·돛천 제작.
- `tools/ship3d/galleon_detail.js`: 갤리온의 고유 장식.
- `tools/ship3d/fleet_detail.js`: 나머지 35종의 선체·문화권별 부품. 기존 모델이 선루·갑판집을 만들 때 받은 치수로 장식을 맞춘다.
- `tools/ship3d/ship_finish.js`: 전 선종의 타·조타 설비·닻줄 감개·선수 난간, 갑판집의 지붕·문 마감과 거북선 등판 이음. 선루 높이와 선실·돛대의 위치를 받아 설비를 배치한다.
- `tools/ship3d/runtime_rig.js`: 사각돛·삼각돛·탄자돛·대나무 살 돛·노. 매 프레임 새 모델을 만들지 않고 배열과 인스턴스 변환을 갱신한다. 휜 돛살은 천의 곡면을 따라간다.
- `tools/ship3d/build_runtime.py`: 36종 사양과 제작 원본을 `js/art/ship-models.js`로 묶는다. 생성물은 직접 수정하지 않는다.
- `js/art/ship3d.js`: `G.Ship3D`. 그래픽 장치 하나에서 현재 선종만 유지하고 전환 때 이전 모형 자원을 해제한다. 정적 부품은 재질별로 합치며, 거북선 쇠못 같은 인스턴스도 각각의 변환을 보존한다.
- `js/data/seafx.js`: `G.FX.ship3d`는 표시·조명·움직임, `G.FX.shipArt.families/profiles`는 선종별 색과 부품 유형이다. 초기 갤리온 조정 이름 `G.FX.galleon3d`는 같은 객체를 가리키고, 그 안의 `art`도 갤리온 프로필과 연결되어 있다.

모델 좌표의 크기를 바꾸지 않고, 큰 노·부판·돛에 필요한 렌더 타깃 여백만 늘린다. `G.Ship3D.draw()`는 비활성화·지원하지 않는 선종·장치 손실 때 `false`를 반환하여 기존 이미지로 돌아간다. 항해 장면을 떠나면 자원을 해제한다. 초기 `G.Galleon3D` API와 `test_galleon_3d.html`도 유지한다.

공용 스프라이트 제작 원본 `ship3d_models.js`와 기존 36종 이미지 시트는 수정하지 않았다. 게임은 서버·CDN·fetch·npm 없이 `file://`로 실행된다. 제작할 때만 다음 명령을 사용한다.

```powershell
python tools/ship3d/build_runtime.py
```

## 스킬

개인 스킬 폴더 `~/.codex/skills/realtime-ship-art/`에 설치했다. 실제 파일은 이 작업 환경에서 `C:/Users/User/.codex/skills/realtime-ship-art/SKILL.md`다. 기본 자동 선택을 유지하고 `$realtime-ship-art`로도 호출할 수 있다.

스킬에는 선종별 작업 목록 대조, 문화권·선형 보존, 구조 부품과 재질 보강, 돛·노 연결, 모델 자원 관리, 전체 접촉 시트와 브라우저 검증을 정리했다. `references/plus-ultra.md`에는 이 저장소의 제작 원본·실시간 연결·검사 경로를 둔다. 스킬 생성기의 검증을 통과했고, 실제 35종 확장 작업에 사용했다.

## 검증

```powershell
# NODE_PATH는 이 환경에서 Playwright가 설치된 node_modules를 가리킨다.
$env:SHIP3D_GPU = '1'
node tests/ships3d_smoke.cjs

$env:SHIP3D_GPU = '0'
node tests/ships3d_smoke.cjs
```

검사 항목은 다음과 같다.

- 게임 목록·모델 목록·미술 프로필 36종의 일치, 모든 선종 실제 렌더링
- 7개 방향(인접 각도 포함), 돛 전개·50%·접기, 노 세기 변화의 픽셀 차이
- 네 종류 돛에서 접기 3단계·좌우 바람과 활대 회전 중 입체 밧줄 끝과 실제 천 꼭짓점의 일치, 밧줄 좌표의 유한값
- 반복 동작 중 모형·재질 수 유지, 전체 선종을 바꾸어도 그래픽 장치 한 개 유지
- 렌더 타깃 테두리의 잘림, 외부 전역 이름 누출, 선종 규칙 자료 변조
- 비활성화·없는 ID·그래픽 장치 손실과 복구·해제 후 재생성
- 실제 `index.html` 항해에서 11개 대표 선종으로 기함 전환, 그리기 전후 저장 상태 동일, 장면 종료 자원 해제
- `pageerror`·`console.error` 0, 모든 시험 브라우저 종료

모든 36종의 확대 검토 이미지는 `artifacts/fleet3d-polish2-20261031/gpu/fleet-1.png`부터 `fleet-4.png`까지 아홉 척씩 담았다. `preview.png`는 비교 화면, `sea-balsa.png`는 실제 항해 연결이다. 모드별 검사 기록은 `gpu/report.json`과 `software/report.json`에 있다. 빠른 시각 반복에만 쓰는 `SHIP3D_SKIP_SEA=1`의 기록은 실제 항해 검증을 뜻하지 않는다. `SHIP3D_ARTIFACTS` 환경 변수로 검사 결과 폴더를 지정할 수 있다.

성능 기록의 `benchmarks`는 기함 표시 길이 66에서 초기 준비 4회 이후 14회 측정한 값이다. 픽셀 읽기를 포함하며 게임 전체 FPS 또는 처음 모형을 만드는 비용을 뜻하지 않는다. 실제 GPU와 SwiftShader 결과를 별도로 확인한다. 소프트웨어 렌더링은 확대 시 느릴 수 있다.

실제 항해 시험은 `DOMContentLoaded` 이후 게임 코드·이미지 준비와 지도 자료를 기다린다. 전체 이미지의 `load`를 30초 안에 기다리던 시험이 한 번 시간 초과되어 준비 기준을 바꿨으며, 해당 기록은 `gpu/navigation-timeout-before-wait-fix.json`에 보존했다.

최종 GPU·소프트웨어 검사 모두 36종, 실제 항해 11종, 오류 0으로 통과했다. 한 장치를 유지한 채 36종을 전환했고 각 선종의 반복 동작에서 자원 증가가 없었다. 현재 선종에 따라 7,102~42,736개 삼각형과 18~36회 그리기 호출을 사용한다.

실제 GPU는 NVIDIA GeForce RTX 3050 / ANGLE D3D11, 소프트웨어는 ANGLE Vulkan SwiftShader로 확인했다. Windows 소프트웨어 시험에는 `--use-gl=angle --use-angle=swiftshader`를 명시한다. 초기 `--use-gl=swiftshader`만 사용한 실행은 첫 화면에서 장치가 끊겨 이 최종 성능 수치에 포함하지 않았다.

| 기함 길이 66 | 실제 GPU 중앙값 | SwiftShader 중앙값 |
|---|---:|---:|
| 갤리온 | 2.5ms | 33.5ms |
| 갤리어스 | 1.2ms | 19.1ms |
| 보선 | 1.7ms | 31.6ms |
| 거북선 | 1.3ms | 15.0ms |
| 발사 | 1.2ms | 7.7ms |

또한 `tools/pages.py`가 읽는 배포용 스크립트 목록에서 라이브러리→모델→렌더러→항해의 순서와 각 파일의 단일 포함을 확인했다. 스킬의 본문·UI 메타데이터·참조 경로도 검증했다.

## 남은 범위

이번 작업은 절차적 모델의 미술·움직임 확장이다. 실제 승무원, 근접 촬영용 고밀도 조각 장식, 손상 단계별 외형, 선체의 수면 반사와 바다 공유 깊이 버퍼는 구현하지 않았다. 대항해시대 온라인과 동등한 완성도를 입증했다는 뜻은 아니다.
