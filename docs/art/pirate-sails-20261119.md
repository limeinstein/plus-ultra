# 해적선 검정·와인색 돛 (2026-11-19)

검정 돛과 짙은 와인색 돛 두 가지 도색을 기존 36개 선종에 적용한다. 선체·돛대·돛살·노·갑판 설비는 원래 선종의 형태를 유지한다. 현상수배 명부의 이름난 해적, 소굴 두목, 일반 해적 모두 사용한다.

추가 선체 마감: 검정 배는 숯색 외판·회청색 선루·회은색 장식에 빛바랜 갑판과 도장이 벗겨져 목재가 드러나는 마모를 넣는다. 와인색 배는 마호가니 외판·청록색 선루·황금색 장식과 꿀빛 갑판에 낮은 거칠기와 높은 광택을 적용한다. [두 스타일 확대 비교](../../artifacts/pirate-sails-20261119/hull-finish-closeup.png).

- 해적 두목 ID로 색을 고정한다. 같은 함대의 배들은 같은 색이며 재등장, 항해에서 해전으로 전환, 해전 저장 복원에도 유지된다. 이름 없는 무리는 함대 ID를 사용하고, 오래된 자료에 ID가 없으면 해역을 기준으로 고른다.
- 팔레트: `js/data/seafx.js`의 `G.FX.pirateShips`. 공통 적용: `G.Art.pirateLook(look, npc)`.
- 3D는 기존 돛천의 솔기와 명암을 유지하며 물들인다. 3D 비활성·실패 때는 해당 색의 절차적 선박 그림을 쓴다. 원래 돛 색이 박힌 촬영 시트는 해적 도색에 쓰지 않는다.
- 선체 재질은 제작 원본 `tools/ship3d/ship_detail_materials.js`와 `turtle_detail.js`에서 역할을 표시하고 `python tools/ship3d/build_runtime.py`로 묶는다. 런타임 `js/art/ship3d.js`는 역할별 도색과 위치에 고정된 마모 무늬를 적용한다. 기존 판재 지도·못·이음·요철을 유지하며 추가 그림 지도나 모형을 만들지 않는다. 도색을 바꿀 때 재질의 거칠기·광택·자체 발광을 복원하고, 다시 쓰는 그림도 선체 도색이 다르면 갱신한다.
- 선종 ID·선박 능력치·출현 확률·현상금·저장 형식은 바꾸지 않는다. 아군과 상선·해군에는 적용하지 않는다. 유령선 전용 색은 기존처럼 우선한다.

## 검토 그림과 검사

[검정 돛 36종](../../artifacts/pirate-sails-20261119/black-fleet.png) · [와인색 돛 36종](../../artifacts/pirate-sails-20261119/wine-fleet.png)

`node tests/pirate_sails_smoke.cjs`

72개 도색을 실제 Chromium에서 그리고, 대표 선종의 방향·돛 접기, 두 색의 구분, 아군 색 복원, 반복 도색의 자원 유지와 3D 비활성 대체 그림을 확인한다. 전체 네임드 해적의 색 고정, 실제 항해·해전·저장 복원에서 갤리온과 정크의 도색, 장면 종료의 자원 해제 및 콘솔 오류를 검사한다. 결과는 `artifacts/pirate-sails-20261119/report.json`에 남긴다. 시험 브라우저는 성공·실패 모두 종료한다.

추가 선체 검사에서는 돛과 깃발 색을 같게 맞춰 선체만의 차이를 확인하고, 마모를 끈 그림과 비교한다. 같은 배의 일반→검정→와인→일반 전환에서 원래 그림·거칠기·광택·자체 발광 복원, 반복 전환의 그림 지도·기하·셰이더 프로그램 수 유지, 그래픽 장치 손실·복구 후 도색 유지를 검사한다.

시각 검사가 끝난 뒤 연결 검사만 다시 실행할 때는 `node tests/pirate_sails_smoke.cjs --integration-only`를 쓴다. 확대 비교만 그릴 때는 `--preview-only`를 쓴다.

최종 검사: `node tests/pirate_sails_smoke.cjs` 통과. 36개 선종×두 도색, 확대 선체 4종의 마모·광택·원래 재질 복원, 대표 10종의 방향·돛 접기·대체 그림·자원 수 유지, 그래픽 장치 손실·복구, 네임드 156명의 색 고정과 실제 항해·해전·저장 복원 연결을 확인했다. 콘솔 오류 0건, 시험 브라우저 종료 완료.
