# 갤리온 실시간 3D 시제품 · 2026-10-31

이 문서는 최초 갤리온 단계의 기록이다. 이후 36종 공용 렌더러로 확장했다. 최신 원본 경로·적용 범위·검증은 [전 선종 제작 기록](fleet3d-polish.md), 확인 화면은 `test_ships_3d.html`을 참고한다. 기존 갤리온 비교 페이지와 API는 계속 사용할 수 있다.

항해 기함이 `galleon`이면 지도 위에서 실시간 3D로 그린다. 현재 지도 투영과 수면 피벗, 기함 길이 66을 사용한다. 선회 각도는 연속해서 반영하고, 기존 항해 연출에서 받은 `rig`·`pose`·`furl`로 돛, 깃발, 파도에 따른 자세를 움직인다. 구름에 따라 햇빛 세기도 달라진다.

## 확인 방법

- 저장소의 `test_galleon_3d.html`을 더블클릭한다. 기존 8방향 이미지와 실시간 모형을 나란히 비교한다.
- 배 방향·바람 방향·돛 접기·파도·구름을 조절한다. 표시 크기의 **세부 장식 살펴보기**는 선체 길이 360으로 더 크게 보여준다.
- `index.html` 게임에서는 갤리온을 기함으로 삼고 출항한다. 선박 ID·능력·저장 데이터는 변경하지 않는다.
- `G.FX.galleon3d.enabled = false`로 이전 표시를 비교할 수 있다. 그래픽 장치가 중단되면 기존 이미지로 표시하고, 복구되면 3D로 돌아온다.

## 구현

- `js/art/galleon3d.js`: 한 번 만든 선체와 삭구를 재질별로 합친다. 돛과 깃발은 같은 꼭짓점 배열을 갱신한다. 매 프레임 모형을 다시 만들지 않는다.
- 작은 투명 WebGL2 캔버스에 모형을 렌더링한 뒤 항해의 기존 Canvas 2D 순서에 합성한다. 항적·물보라·도시·알림과의 표시 순서가 이어진다.
- 미술 보강 후 모형은 38,200개 삼각형, 32개 그리기용 모형, GPU에 올라가는 텍스처 6개다. 최초 시제품은 10,212개 삼각형과 29개 그리기용 모형이었다. 정적 장식을 재질별로 합쳐 그리기 호출 증가를 줄였다.
- 항해 화면을 떠나면 모형·재질·텍스처·그림자 대상·WebGL 장치를 해제한다. 다시 항해하면 새로 준비한다.
- `js/art/galleon-model.js`는 기존 `tools/ship3d/ship3d_models.js`·`ship3d_tex.js`, 갤리온 사양, 전용 미술 원본 `tools/ship3d/galleon_detail.js`를 묶어 생성한다. 공용 36종 모형 원본과 기존 시트 제작은 바꾸지 않았다.
- `js/vendor/three-r147.js`는 기존 제작 도구와 같은 three.js 0.147.0의 로컬 사본이다. 라이선스는 `js/vendor/THREE-LICENSE.txt`. 라이브러리와 모형의 전역 이름도 `G` 아래에 둔다.
- 게임 실행에는 서버·npm·외부 CDN·모듈 import·fetch가 필요 없다. `index.html`의 스크립트 목록을 통해 단일 파일판에도 포함된다.

생성물을 다시 만드는 명령:

```powershell
python tools/ship3d/build_runtime.py
```

이 제작 명령에만 Python/Pillow와 `tools/procedural_art/node_modules/three`의 0.147.0 원본이 필요하다.

## 주요 조정값

모든 연출 조정값은 `js/data/seafx.js`의 `G.FX.galleon3d`에 있다.

| 값 | 기본값 | 용도 |
|---|---:|---|
| `enabled` | true | 항해 기함 갤리온의 3D 표시 |
| `minBuffer` / `maxBuffer` | 192 / 768 | 실제 렌더링 캔버스의 한 변 |
| `supersample` | 1.5 | 화면 표시보다 크게 그린 뒤 축소 |
| `shadowSize` | 512 | 자체 그림자 해상도 |
| `shadowMinLen` | 100 | 이보다 작은 지도 표시에서는 자체 그림자 생략 |
| `elevation` | 0.52 | 기존 선박 시트와 같은 내려다보기 투영 |
| `maxBrace` | 0.75 | 돛 활대의 최대 회전각 |
| `foldHeight` | 0.045 | 돛을 모두 접었을 때 남는 높이 |
| `sailFoot` / `sailLeech` / `sailCrease` | 2.3 / 0.035 / 0.22 | 돛 발끝의 들림·옆선의 오목함·장력 주름 |
| `art` | 색 8종·표면 깊이 2종 | 목재·청록 도색·돛천·밧줄의 색과 표면 깊이 |

## 추가 미술 보강

- 선체: 더 촘촘한 목재 판재와 이음매·나무못, 표면 요철, 어두운 외판 띠와 황동 테.
- 선미: 청록 도색, 마름모 금박, 둥근 창 윗부분과 십자 창살, 양옆 회랑, 뒤쪽 발코니와 선미 등.
- 갑판: 목재 난간 기둥, 선루 계단 두 곳, 격자 덮개, 손잡이 달린 캡스턴, 열린 구명정과 벤치, 물통과 밧줄 묶음.
- 현측: 포문 덮개·포신 테, 양옆 닻과 고정줄, 돛대 지지줄 아래 도르래와 연결줄.
- 돛: 1024px 절차적 천 재질에 폭별 색 차이·솔기·바느질·리프 끈·모서리 보강천을 넣었다. 사각돛 격자를 늘리고 바람을 받은 배부름, 안으로 당겨진 옆선과 들린 아랫자락을 연결했다.

비교 페이지의 확대 모드와 시험 결과의 `art-details.png`에서 선미·선수·현측·접은 돛을 확인한다. 재질 그림은 실행 때 Canvas로 만들므로 추가 다운로드가 없다. 표면 색은 `G.FX.galleon3d.art`에서 조절하고, 모형을 다시 생성하는 장면 재진입 때 반영된다.

이번 미술 전후 화면은 `artifacts/galleon-art-20261031/before.png`·`after.png`, 네 방향 상세 화면은 `details.png`에 보관했다.

## 검증

```powershell
# NODE_PATH에 playwright가 설치된 node_modules를 지정할 수 있다.
node tests/galleon3d_smoke.cjs

# Windows의 실제 그래픽 장치 경로로 같은 검사를 실행한다.
$env:GALLEON_GPU = '1'
node tests/galleon3d_smoke.cjs
```

시험은 브라우저를 `finally`에서 닫는다. 확인 항목:

- `file://`에서 비교 화면과 실제 `index.html` 항해 장면 실행, 콘솔 오류 확인
- 1도 차이를 포함한 12개 방향, 돛 0·50·100%의 실제 화면 차이
- 반복 동작 중 모형·텍스처 수 유지
- 비활성화·다른 선종·그래픽 장치 손실 때 기존 그림으로 넘김, 장치 복구와 해제 후 재생성
- 실제 항해 연결, 그리기 전후 저장 상태 동일, 항해 장면 종료 때 자원 해제
- 기함 크기와 확대 크기에서 준비 이후 호출 시간 및 GPU 완료 대기를 포함한 시간 측정

결과와 화면은 `artifacts/galleon3d-20261031/`에 있으며, 실제 GPU 결과는 그 안의 `gpu/`에 있다. 보고서의 `Submit`은 호출 시간, `Readback`은 픽셀을 읽어 GPU 완료까지 기다린 시간이다. **게임 전체의 프레임 속도가 아니다.** 첫 모형 생성과 셰이더 준비 시간도 중앙값에 포함하지 않는다. 소프트웨어 렌더링 결과는 실제 GPU와 따로 판단한다.

실측 GPU는 **NVIDIA GeForce RTX 3050 / ANGLE D3D11**이다. 미술 보강 후 4회 준비 뒤 24회 측정한 결과:

| 표시 | 측정 방식 | 중앙값 | 95백분위 |
|---|---|---:|---:|
| 기함 길이 66 | 3D 호출 시간 | 1.1ms | 1.5ms |
| 기함 길이 66 | GPU 완료 대기·픽셀 읽기 포함 | 5.4ms | 7.5ms |
| 확대 길이 240 | GPU 완료 대기·픽셀 읽기 포함 | 7.0ms | 8.2ms |

GPU 검사에서 콘솔 오류 0, 그리기 전후 저장 상태 동일, 장면 종료 자원 해제, 그래픽 장치 손실과 복구, 반복 재생 자원 수 유지가 모두 통과했다. 실행별 편차가 있으므로 이전 측정치와의 단순 차이를 성능 개선으로 해석하지 않는다. 기존 `tests/shipsprites_browser_smoke.js`의 시트 준비와 북동 조타 검사는 최초 시제품 단계에서 통과했고, 이번에는 공용 시트 코드를 수정하지 않았다.

SwiftShader에서도 같은 기능 검사와 콘솔 오류 0을 확인했다. GPU 완료 대기를 포함한 중앙값은 기함 길이 66에서 31.0ms, 확대 길이 240에서 100.0ms였다. 하드웨어 가속 없는 환경에서 확대 표시가 부드럽다는 뜻은 아니다. 모든 시험 브라우저는 종료했고 남은 시험 과정이 없는 것을 확인했다.

## 시제품 범위

항해 기함 갤리온 한 척에 적용했다. 동행선·NPC·해전은 기존 그림이다. 실시간 기반에 선체·장식·갑판 설비·돛천을 보강한 단계이며, 대항해시대 온라인과 동등한 완성도를 검증한 것은 아니다. 근접 감상용의 조각 장식과 인물, 세월에 따른 손상 표현은 아직 없다.

바다는 기존 지도 셰이더다. 선체 수면선의 자르기와 기존 물보라는 연결했지만, 선박의 실제 수면 반사나 바다와 공유하는 3D 깊이 버퍼는 없다. 현재 66px 기함 표시에서는 세부 차이가 작으므로 비교 화면의 확대 표시에서 돛과 선회를 함께 확인한다.
