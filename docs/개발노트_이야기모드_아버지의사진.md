# PLUS ULTRA 개발노트 — 이야기 모드 「아버지의 사진」 (2026-10-08)

요청: 사용자가 준 이야기(1480년 포르투갈, 행방불명된 시간 여행자 아버지가 남긴 「조선 유적 앞 현대의 사진」, 남작의 아들과 떠나는 여행, 아버지 흔적을 따라 이슬람 → 인도 → 신대륙 → 중국 → 일본 → 한반도 → 아틀란티스)를 바탕으로, 스토리 기반 플레이가 되는 캐릭터를 만든다. 주인공 = 하얀 남방의 항해사(첨부 그림 = 기존 `portraits/player/navigator_white`), 친구(남작의 아들) = 카사노바 기반(사용자가 확인한 얼굴 = 기존 `portraits/player/casanova`).
사용자 결정: 범위 = 시작 + 아버지 흔적 사슬 전체 / 주인공 **마테우스 다 코스타** / 친구 **자코모 카사노바** / 어머니는 남작이 공경하는 「부인」(연애 아님).

상태: **폴더(WebGame)에 반영, 커밋·배포 전.** 새 파일 `js/data/story.js`·`js/systems/story.js`·`tests/story_smoke.js`. 연결: `index.html`(data: storycrew 다음 / systems: tutorial 다음), `catalog.html`, `title.js`(단추), `city.js`(`arg.story` → 프롤로그), `info.js`(탭 「아버지의 사진」·단서 출처 `story`), `cabins.js`(`lgk` 말 배우기 배율), `seacaptains.js`(tale 동료는 철새 제독이 되지 않음), README 절.
`Claude outputs/story_photo_2026-10-08.patch`는 `git diff`라 **같은 파일에 있던 다른 세션의 배포 전 변경도 섞여 있다** — 참고용.
(프로젝트 문서 용량이 차서 이 노트는 프로젝트 대신 `docs/`에 둔다.)

## 설정 (js/data/story.js `G.STORY`)
- 제독: 마테우스 다 코스타, PT, 탐험가(항해 2·측량 2·운용 1), 22세(1458년생), 능력 54/66/50/62, 포르투갈어 3·스페인어 2·로망스어 1, 금화 2,500, 보통 난이도, 배 카라벨 「도나 레오노르」(어머니 이름). 로코 없음.
- 동료(모두 `tale: true`, 처음 충성 85): `giacomo` 자코모 카사노바(부관 · it · 48/76/44/94 · 요리 2·의술 2·웅변 2·측량 1 · PT3 IT3 ES2 EN1 · 월급 30 · `face: portraits/player/casanova`, `halfKey: characters/player_half_casanova`, `lgk: 2`) / `anselmo` 안셀무 신부(측량사 · 신학 3·역사 3·측량 1·의술 1 · PT3 라틴3 게르만3 아랍1 · 월급 50) / `estevao` 에스테방 누네스(항해사 · 항해 3·운용 2·검 2·포 2·요리 1 · 월급 90).
- 후원자 `pt_casanova` 카사노바 남작(리스본 저택, pw 2, wealth 3, 취향 유적·지리·보물, 1480~1530 「조반니 카사노바 남작」, `tale: true`). 아버지의 손목시계를 임금께 바쳐 남작이 된 인연.
- 아버지 김도현(리스본 이름 「도앙」, 2100년 대한민국 시간 여행 연구소 말단, 1456년 리스본 부두에 불시착). 두 해마다 머물렀던 자리로 다시 떨어지고 늙지 않음. 마테우스가 열두 살(1470) 뒤로 리스본에 못 돌아온 까닭 = 아틀란티스가 끌어당김(다음에 떨어지면 못 떠남). 어머니 레오노르는 알지만 마녀재판이 두려워 「원래 그런 분」이라고만.
- 흔적 일곱(도시 발견물, cat treasure, `needHint`+`need` 사슬, 가치 2,600~8,000×1.75): ft_granada(10, 1460) → ft_cairo(79, 1464) → ft_delhi(145, 1468) → ft_cuzco(223, 1472) → ft_hangzhou(177, 1474) → ft_sakai(192, 1476) → ft_hanyang(190, 1478). 장면(scene)·리스본의 기억(memory)·다음 단서(next). 한양 편지 next = knossos·gibraltar·timaeus(아틀란티스 사슬 `chaindisc.js`) + 소지품 「아버지의 시계」.

- 사진 `ST.photo`: 글로 묘사(하늘빛 짧은 옷·검은 테 안경 / 겹처마 전각·돌난간 / 작은 판을 든 사람들). `images/story/photo`가 있으면 수첩에 그 그림, 없으면 코드로 그린 빛바랜 사진 틀.

## 진행기 (js/systems/story.js `G.Story`)
- 읽어 들일 때 `register()`: 흔적을 `G.DISCOVERIES/G.DISC`에(discoveries.js가 이미 돈 뒤라 add와 같은 꼴로 직접), 동료를 `G.MATES/G.MATE/G.MATE_RANGE`에, 남작을 `G.SPONSORS/G.SPONSOR`에.
- `begin()` 타이틀 창 → `start()`(상태) → `Game.go('city', {cityId: 0, story: true})` → city.js가 `G.Story.prologue(c)` → intro(어머니) · harbor(세 사람) · baron(남작, 고르기 하나) · `contract()`(교섭 없이 선금 1,500·사례 4,000·2년, 알함브라 단서 + ft_granada 단서) · after(에스테방·자코모 길 안내).
- 감싼 함수: `Disc.available`·`Disc.addHint`(tale 발견물은 이야기 모드에서만), `Disc.find`(찾은 뒤 `onFind` — 장면·기억·다음 단서 / 아틀란티스면 끝), `Frontier.mateReady`(tale 동료), `Sponsor.present`(tale 후원자), `Img.chain.mateHalf`(halfKey 먼저), `Scenes.sea.update`(끝난 뒤 다시 들르기).
- `ST.hint(id)`: 개척 단계·연쇄 조건을 건너뛰고 `s.hints[id] = {src:'story'}`(수첩 출처 「아버지의 자취」).
- 말하는 사람: P 주인공 · G/A/E 동료 · M 어머니(`npcSpec('story_mother','noble','ib','f')` + `portraits/npc/story_mother`) · F 아버지(`'kr' scholar` + `portraits/npc/story_father`) · B 남작(`Sponsor.speaker`) · keeper(흔적마다 고장 사람: 안내인·커피집 주인·탑지기·노인·찻집 주인·스님·노승 — `C.npc`). `{name}`·`{kin}`(대를 이으면 할아버지)·`{father}`·`{mother}`.
- 저장: `s.story = {found[], end, started, prologue, letter, endDate, lastMeet, earlyAtlantis}`. 자동 저장은 보통 칸(0).

## 인물 그림 (2026-10-08 반영)
- 레오노르·김도현·안셀무 신부·에스테방·카사노바 남작의 전용 얼굴과 머리~무릎상을 추가했다. 자코모는 처음부터 쓰던 `casanova` 얼굴·무릎상을 그대로 쓴다.
- 다섯 인물은 얼굴·시선·어깨·몸통이 플레이어를 향하는 정면 구도로 다시 제작했다.
- 김도현은 낡고 얼룩진 흰 연구실 가운을 중심으로, 팔뚝에 묶은 낡은 넥타이와 1480년 리스본에서 얻은 포르투갈식 린넨 셔츠·가죽 허리띠·작은 주머니·모직 어깨 망토를 섞었다.
- 파일: `portraits/npc/story_mother·story_father`, `portraits/mates/anselmo·estevao`, `portraits/sponsors/pt_casanova`와 각 `_half`.
- 거리 보행 NPC의 대화 초상은 옆을 보는 보행 시트 확대본 대신 문화권별 정면 역할 원화와 어린이 원화를 사용한다(`portraits/street-folk`, 20문화권×13명×얼굴/무릎상 = 520장).
- 거리 NPC 13역할은 보행 스프라이트의 역할 키(`town_man`·`town_woman`·`boy`…`navigator`)와 대화 초상 파일명을 1:1로 맞췄다. 새 거리·이야기 초상은 모두 RGBA WebP이며 배경은 완전 투명하다.
